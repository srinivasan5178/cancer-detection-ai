# Dataset Instructions

## 1. Dataset

This project performs five-class image classification using a DenseNet201 and EfficientNetV2L feature-fusion pipeline with Grey Wolf Optimization (GWO) for CatBoost hyperparameter tuning.

Use the LC25000 dataset only if you have the right to access and use it. Download it from its authorized source; do not commit the full dataset to this repository unless redistribution is permitted.

## 2. Expected folder structure

The pipeline expects images to be organized by class. Set `DATASET_ROOT` to the directory that contains the class folders.

```text
Project_Sample/
├── class_1/
│   ├── image_001.jpg
│   └── ...
├── class_2/
│   ├── image_001.jpg
│   └── ...
└── ...
```

For LC25000, use the dataset's actual class-folder names. Do not rename or combine classes unless the experiment protocol explicitly requires it. If your downloaded archive has an extra parent directory, point `DATASET_ROOT` to the directory directly containing the class folders.

## 3. Configure the dataset path

In `Complete_Fusion_Pipeline_Flow.ipynb` or `complete_fusion_pipeline.py`, set:

```python
DATASET_ROOT = "/content/Project_Sample"  # Google Colab example
```

For a local Windows environment, use a raw string, for example:

```python
DATASET_ROOT = r"C:\path\to\Project_Sample"
```

Check that the path exists and that every expected class folder contains readable image files before training.

## 4. Data split and leakage prevention

- Split original images into training, validation, and test partitions **before** applying oversampling or any other data augmentation.
- Apply oversampling/augmentation to the training partition only.
- Use validation data for model selection and GWO-CatBoost hyperparameter tuning.
- Keep the test set independent until the final evaluation.
- If multiple images originate from the same patient, specimen, slide, or source, use a group-aware split where possible so related images cannot leak across partitions.
- Do not use test-set results to select epochs, features, thresholds, or hyperparameters.

The pipeline's configured split ratios should be checked in the notebook/script before running. Report the actual class counts and split sizes generated by the experiment.

## 5. Image preprocessing

Use the preprocessing required by the selected pretrained DenseNet201 and EfficientNetV2L backbones. Keep input image size, color-channel handling, normalization, and augmentation consistent with the implementation and document any changes. Do not assume that one backbone's preprocessing is automatically appropriate for the other.

## 6. Recommended dataset checks

Before training, verify:
- class names and image counts;
- unreadable/corrupt files and duplicate images;
- image dimensions and color mode;
- class imbalance in each split;
- patient/specimen/source overlap between splits, when source identifiers are available;
- the final train/validation/test counts saved with the experiment.

## 7. Reproducibility

Record the dataset source/version, download date, class mapping, random seed, split ratios, image size, preprocessing, augmentation, and package versions. Do not publish private, licensed, or restricted images. A small text file containing dataset provenance and class counts is preferable to uploading the entire dataset.
